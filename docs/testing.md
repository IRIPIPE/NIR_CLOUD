# Фактические результаты испытаний

## Контрольная точка 1. Локальный запуск API и базы данных

Проверено 22 ноября 2026 года в Linux x86-64. На хосте использованы Docker Engine 29.10.0 и Docker Compose 5.8.0. В контейнерах запущены Python 3.12.15 и PostgreSQL 16.14.

| Проверка | Действие | Фактический результат |
| --- | --- | --- |
| Запуск с пустыми томами | `docker compose up --build -d --wait --wait-timeout 60` | Созданы два отдельных тома. Оба контейнера получили статус `healthy`. |
| Соединение приложения с PostgreSQL | `GET http://127.0.0.1:8000/health` | HTTP `200`, ответ `{"status":"ok","database":"ok"}` после `SELECT 1`. |
| Документация API | Запросы к `/docs` и `/openapi.json` | Оба вернули HTTP `200`. В OpenAPI у `GET /health` описаны ответы `200` и `503`. |
| Управляемый отказ базы и восстановление | `docker compose stop db`, затем запрос к `/health`. После `docker compose up -d --wait` запрос повторён. | Сбой воспроизводится на этапе подключения FastAPI к остановленной базе. API отвечает HTTP `503` с `{"status":"unavailable","database":"unavailable"}`. После запуска базы снова HTTP `200`. |
| Сохранность двух томов | Записаны контрольная строка в PostgreSQL и файл в `/data/uploads` от имени пользователя API. Затем выполнены `docker compose down` и `docker compose up -d --wait`. | После пересоздания контейнеров прочитаны та же строка и тот же файл. API вернул HTTP `200`. Контрольные данные удалены после проверки. |

Демонстрация с учётными записями и `test.pdf` относится к последующим проверкам прототипа.
